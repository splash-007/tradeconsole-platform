# Trade Console — Complete PostgreSQL Table & Field Definitions

> **Origin Legend**:  
> `EXISTING` = field already used by current application  
> `IMPLIED` = required by current UI/workflows but not explicitly named  
> `RECOMMENDED` = needed for proper production architecture

## GROUP 1: AUTHENTICATION & SECURITY

---

### `users`
Core authentication identity for all platform users (customers and staff).

| Column | Type | Null | Default | Unique | Indexed | FK | Origin | Description |
|--------|------|------|---------|--------|---------|-----|--------|-------------|
| id | uuid | no | gen_random_uuid() | yes | yes | — | EXISTING | Primary identifier (public-safe) |
| email | text | no | — | yes | yes | — | EXISTING | Login email address |
| username | text | yes | null | yes | yes | — | RECOMMENDED | Unique username (generated by backend on provisioning; NULL before provisioning) |
| password_hash | text | yes | null | no | no | — | RECOMMENDED | Argon2id hash. NULL is permitted only before account activation. Once account_activated=true, a valid hash is required. |
| role | text | no | — | no | yes | roles.key | EXISTING | Current role key |
| status | text | no | 'active' | no | yes | — | EXISTING | active / suspended / disabled |
| email_verified | boolean | no | false | no | no | — | RECOMMENDED | Email verification flag |
| must_change_password | boolean | no | false | no | no | — | RECOMMENDED | Force password change on next login |
| account_activated | boolean | no | false | no | no | — | RECOMMENDED | True once customer has completed activation (set password). Required to be true for login. |
| activation_token_hash | text | yes | null | no | no | — | RECOMMENDED | SHA-256 of activation/set-password token. NULL after activation. |
| activation_token_expires_at | timestamptz | yes | null | no | no | — | RECOMMENDED | Activation token expiry. Token is invalid after this time. |
| created_at | timestamptz | no | now() | no | yes | — | EXISTING | Account creation time |
| updated_at | timestamptz | no | now() | no | no | — | RECOMMENDED | Last update time |
| last_login_at | timestamptz | yes | null | no | no | — | IMPLIED | Last successful login |
| archived_at | timestamptz | yes | null | no | no | — | RECOMMENDED | Soft delete timestamp |

**Relationships**: One-to-one with `customer_profiles` or `staff_profiles` depending on role.

**Security rules**:
- `password_hash` may be NULL only before `account_activated = true`.
- Once `account_activated = true`, a valid Argon2id hash is required.
- `activation_token_hash` must be stored hashed (SHA-256 of the raw token). Never store the raw token.
- Activation tokens must expire. Check `activation_token_expires_at` before accepting.
- Do NOT email permanent or temporary plaintext passwords. Use the activation/set-password link flow.

## GROUP 7: FINANCE

---

> **Double-Entry Ledger Architecture**  
> The production financial ledger is genuinely double-entry.  
> Structure: `ledger_transactions → ledger_entries → accounts`  
> Every finalized ledger transaction must balance debits and credits.  
> Ledger entries are immutable and are the source of truth for all balances.  
> System/clearing/fee/settlement accounts are supported alongside customer accounts.  
> A mutable customer balance field must NOT be used as financial source of truth.
